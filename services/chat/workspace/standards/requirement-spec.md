# 需求规格说明标准（requirement-spec）

一份可以进入设计/评审阶段的完整需求说明，必须包含以下要素：

## 必备要素

1. **需求标识**：单号、标题、当前状态
2. **背景与目标**：为什么做、解决谁的什么问题、可衡量的价值
3. **目标用户**：角色清单与典型使用场景
4. **功能需求**：功能点列表，每项含优先级（P0 必须 / P1 重要 / P2 一般 / P3 可选）与验收口径
5. **非功能需求**：性能、安全、可用性、兼容性
6. **范围边界**：明确做什么、不做什么
7. **约束与依赖**：技术栈、工期、预算、上下游系统依赖
8. **验收标准**：可测试的通过条件

## 完整性判定规则

- **阻塞级**：背景目标、功能需求、验收标准任一缺失 → 判定为不完整
- **重要级**：非功能需求、范围边界缺失 → 可进入评审但需限期补齐
- 仅有一句方向性描述、无可验收细节 → 判定为"想法"阶段

## 报告输出要求

- 分析报告以 Markdown 写入 `reports/` 目录，文件名含需求单号
- 报告开头必须给出结论（完整 / 不完整 + 原因摘要）
- 引用本标准时注明依据的要素编号
